# Мотивационная программа 2026 — трекер команды KWS

Веб-трекер: менеджеры вносят факт продаж по SKU, система считает выполнение волны и приз
в тенге, админ (KWS) закрывает месяцы и видит рейтинг для подарков. 31 участник
(13 Hennessy + 18 Moёt), данные — из программы (`program_data.json`).

## Что умеет
- **Менеджеры** — логинятся, видят только свои точки (сети отдельным блоком, потом по
  каналам), ведут **ежедневный журнал отгрузок**: добавляют дату + штуки по SKU за день;
  можно изменить/удалить любой день. Система сама суммирует в месяц → волну, считает
  % выполнения и приз.
- **Админ (KWS)** — дашборд по всем точкам с группировкой (СЕТИ / Алматы OFF·ON /
  Астана OFF·ON / Регионы), прогресс по волнам, **месячное закрытие** (после закрытия
  менеджеры не правят отгрузки этого месяца — закрывает только админ), **рейтинг по месяцу**
  (самые растущие точки + команды по заполнению) для подарков до 15 000 ₸.
- Расчёт полностью совпадает с Excel-файлом «Расчёт выплат» (КУ 20%, ставки волн 3/5/7 и
  2/4/6, потолок 110%, командный бонус 1,5% RSP). Приз — по выполнению волны; месячный
  прогресс (план месяца = полволны) показывается отдельно для контроля и подарков.

## Персональные аккаунты менеджеров
Админ → вкладка **«Пользователи»** (`/admin/users`):
- **Добавить менеджера** — имя, логин, команда, пароль (если пусто — `логин-26`).
  Пароль показывается **один раз** сразу после создания: в базе он хранится только
  в зашифрованном виде и восстановить его нельзя, можно только задать новый.
- **Точки** — отметить галочками, какие точки ведёт этот человек (сети идут первым блоком,
  есть кнопки «все» / «снять» по каждой секции). Обычная точка принадлежит одному менеджеру:
  поставив галочку одному, вы автоматически снимаете её у прежнего владельца.
  **Сеть (Metro, Galmart) может быть у нескольких менеджеров сразу** — галочка на сети
  добавляет человека к тем, кто её уже ведёт, ничего не отнимая. Вторая отметка,
  **★ ответственный**, задаёт, за кем сеть числится в командном зачёте: она всегда одна,
  прежний ответственный при передаче остаётся со-менеджером. Все, у кого есть доступ,
  вносят отгрузки наравне; в журнале точки видно, кто внёс каждый день. Если
  ответственного удалить, сеть переходит к со-менеджеру, а не остаётся без владельца.
- **Задать пароль** — сброс пароля прямо из таблицы (минимум 4 символа).
- **Удалить** — удаляется только доступ: точки становятся свободными,
  а все внесённые отгрузки сохраняются.

Командные логины из таблицы ниже создаются при первом запуске как временные —
после того как заведены персональные аккаунты, их можно удалить.

## Логины по умолчанию
| Роль | Логин | Пароль |
|---|---|---|
| Админ (KWS) | `admin` | `kws-admin-2026` |
| Алматы офф-трейд | `almaty_off` | `almaty-off-26` |
| Алматы он-трейд | `almaty_on` | `almaty-on-26` |
| Астана офф-трейд | `astana_off` | `astana-off-26` |
| Астана он-трейд | `astana_on` | `astana-on-26` |
| Регионы | `regiony` | `regiony-26` |

Пароль админа можно задать через переменную окружения `ADMIN_PASSWORD`.
Пароли создаются один раз при первом запуске (при пустой базе).

## Деплой на Railway (новый линк)

**Вариант A — через Railway CLI (без GitHub):**
1. Установить CLI: `npm i -g @railway/cli`, затем `railway login`.
2. В папке трекера: `railway init` (создать новый проект).
3. Добавить базу: в дашборде Railway → **New → Database → PostgreSQL**
   (Railway сам пропишет переменную `DATABASE_URL`).
4. `railway up` — задеплоит папку. Railway выдаст публичный линк.

**Вариант B — через GitHub:**
1. Создать новый репозиторий, залить туда эту папку (`git init && git add . && git commit && git push`).
2. В Railway → **New Project → Deploy from GitHub repo** → выбрать репозиторий.
3. Добавить PostgreSQL (см. выше) — `DATABASE_URL` появится автоматически.

### ВАЖНО про данные
Диск контейнера на Railway **обнуляется при каждом редеплое**, поэтому на Railway приложение
хранит данные только в Postgres. Подойдёт любая из переменных: `DATABASE_URL`
(приватная сеть, рекомендуется — в сервисе задать значение `${{Postgres.DATABASE_URL}}`)
или `DATABASE_PUBLIC_URL` (публичный прокси). Если на Railway нет ни одной из них,
приложение **сознательно не запустится** и в логах напишет, что сделать, — это защита
от тихой записи на временный диск, из-за которой один раз уже пропали созданные аккаунты.
(Осознанно обойти защиту: переменная `ALLOW_EPHEMERAL_DB=1`.)
Локально, без Railway, переменные не нужны — используется SQLite-файл рядом с кодом.

Вторая страховка — резервная копия: в админке на странице **Пользователи** есть кнопка
**«Скачать копию»** (аккаунты, пароли, привязки точек, отгрузки, закрытые месяцы) и
**«Восстановить из копии»** — восстановление только добавляет недостающее, ничего не удаляя.
Скачивайте копию после каждого крупного изменения. Текущее хранилище видно на той же
странице и в `/healthz` (`"persistent": true` = данные переживают редеплой).

## Локальный запуск
```
pip install -r requirements.txt
python app.py
# http://localhost:5000
```

## Обновление данных программы
Если меняются точки/планы (например, после подтверждения договорных планов) — пересоберите
`program_data.json` из `build_excel_v18.py` (тот же генератор, что и Excel) и перезадеплойте.
KU (коммерческие условия) задаётся в `program.py` — сейчас 20% как в файле команды.

## Стек
Flask + SQLAlchemy + gunicorn. Postgres (Railway) или SQLite (локально).
